# Published-skill README standard

Every new skill repository must match the control README's presentation quality. Adapt templates/skill-repository-readme.md to the actual skill.

Include a centered title, one concrete developer benefit, restrained truthful badges and navigation. Follow with capabilities, tested installation and invocation, a realistic example and observed output, a small workflow diagram where useful, verification, scope and upstream/license attribution.

Use the actual supported runtime, repository and CI workflow. License badges require a verified license. Source stars are not derivative adoption. No invented benchmarks, users, savings or guarantees.

Use concise headings, fenced commands, helpful tables and relative links to real files. Fill every placeholder and remove irrelevant sections. Examples must be executable or clearly illustrative.

Before the final artifact fingerprint, review Markdown structure, links, commands, badges, provenance and claim accuracy. Record README quality in final review evidence. Subsequent README changes require applicable artifact-bound review updates. Load this standard only when writing the public README.
